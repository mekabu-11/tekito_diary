# コーディングルール

## コメントの粒度

コードを書く・修正する際は、以下の粒度でコメントを必ず付けること。

### ファイルレベル
- ファイル冒頭に `/** ... */` 形式でファイルの役割・概要を記載
- APIルートの場合: エンドポイント、リクエスト/レスポンスの仕様も含める

### 関数・コンポーネントレベル
- 主要な関数には JSDoc コメント（`/** ... */`）で目的・引数・戻り値を記載
- React コンポーネントには Props の各フィールドに説明を付ける

### 処理ブロックレベル
- ロジックの区切りごとにセクションコメント（`// ========== セクション名 ==========`）
- 状態管理の変数には `// --- カテゴリ名 ---` で分類コメント
- 重要な処理の直前に「なぜその処理をしているか」を一行コメントで記載

### JSX / UIレベル
- UIの主要セクションに `{/* ===== セクション名 ===== */}` コメント
- 条件分岐によるUI切り替えには、各分岐の意味をコメント

### 書かなくてよいもの
- コードを読めば明らかにわかる処理（例: `i++` に「インクリメント」のコメントは不要）
- import 文
