# テスト必須ルール

このワークフローは、機能追加やバグ修正を行う際に必ず従うべきテストポリシーを定義する。

## 機能追加時

1. 新しいAPIルートを追加した場合、`web/src/__tests__/` に対応するテストファイルを作成する
2. 新しい lib ユーティリティを追加した場合、ユニットテストを作成する
3. テスト観点を網羅する:
   - **認証チェック**: 未認証→401、権限不足→403
   - **正常系**: 期待通りのレスポンスが返ること
   - **異常系**: 空入力、null、不正データ時の挙動
   - **エッジケース**: AI レスポンスが予期しない形式の場合のフォールバック
4. `npm test` で全テストがパスすることを確認する
// turbo
5. `npm run build` でビルドが成功することを確認する

## バグ修正時

1. 修正対象のバグを**再現するテストケースを先に追加**する（Red → Green サイクル）
2. バグ修正後にテストがパスすることを確認する
3. 既存テストの期待値が変わる場合は、テストも合わせて更新する
// turbo
4. `npm test` で全テストがパスすることを確認する

## リファクタリング時

1. 変更前に `npm test` を実行し、現在のテストがすべてパスすることを確認する
2. リファクタリングを実施する
3. インターフェースが変わった場合はテストも更新する
// turbo
4. `npm test` で全テストが依然としてパスすることを確認する

## テストの書き方

- テストフレームワーク: **Vitest**
- テストディレクトリ: `web/src/__tests__/`
- ファイル命名規約:
  - APIルート → `api-{ルート名}.test.ts`
  - ライブラリ → `{モジュール名}.test.ts`
- 外部依存（Supabase, OpenAI）は **`vi.mock()` でモック** すること
- テスト名は**日本語**で記述する（例: `it("未認証の場合 401 を返す")`）
- コマンド: テストは `cd web && npm test`、ビルド確認は `cd web && npm run build`
